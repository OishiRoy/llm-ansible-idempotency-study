# Evaluating Idempotency in LLM-Generated Ansible Playbooks: A Repeated-Execution Study

This repository contains the replication package and experimental artifacts
associated with the study **“Evaluating Idempotency in LLM-Generated
Ansible Playbooks: A Repeated-Execution Study.”**

The study investigates the functional correctness and repeated-execution
idempotency of LLM-generated Ansible playbooks. A benchmark of 30
configuration-management tasks was evaluated across three large language
models (LLMs), resulting in 90 generated playbooks.

The repository preserves the prompts, generated playbooks, benchmark
definitions, evaluation scripts, execution logs, processed results, and
figures used in the study.

---

## Research Scope

The study addresses two distinct properties of generated Ansible
playbooks:

- **Functional correctness:** whether a generated playbook successfully
  establishes the requested system state.
- **Repeated-execution idempotency:** whether a functionally correct
  playbook can be executed repeatedly without introducing additional
  changes.

A controlled state-perturbation experiment was additionally conducted on
selected tasks to examine recovery behavior and post-recovery stability.

---

## Benchmark

The benchmark consists of 30 configuration-management tasks divided
equally across six categories:

1. Package Management
2. File and Directory Management
3. User and Access Management
4. Service and Application Configuration
5. System Configuration and Scheduling
6. State and Deployment Operations

Each task was evaluated using playbooks generated by three LLMs:

- GPT-5.6 Sol
- Claude Sonnet 5
- Qwen3.7-Plus

This produced a total of **90 model-task playbooks**.
